# Tick Stock Panel 数据存储方式分析

> 分析对象：`/Users/arcy/work/stock/tick-stock-panel`
> 结论：本项目不依赖外部数据库，采用“本地 Parquet 文件 + JSON/JSONL 用户态存储 + DuckDB 内存视图 + Polars 进程内缓存”的存储架构。

## 1. 总览

- 行情、指标、财务、盘口等业务数据使用 **Parquet** 列式文件持久化。
- 用户偏好、密钥、会话、告警、监控规则、策略覆盖、任务状态等使用 **JSON / JSONL** 持久化。
- DuckDB 只作为 **内存中的视图层**，不生成落盘的 `.db` 文件。
- 热路径数据通过 **Polars 内存缓存** 提供，避免反复扫盘。

## 2. 数据根目录

统一由 `settings.data_dir` 决定，定位逻辑在
[`backend/app/config.py`](backend/app/config.py) 的 `_user_data_root()`：

- 开发模式：项目根目录下的 `data/`
- 打包桌面版：可执行文件同级的 `data/`
- 可用环境变量 `DATA_DIR` 覆盖
- 相对路径会基于项目根目录解析为绝对路径

唯一存储入口是 [`DataStore`](backend/app/tickflow/repository.py)，
启动时创建所有子目录并注册 DuckDB 视图；实际读写编排在
[`KlineRepository`](backend/app/tickflow/repository.py)。

## 3. 两类持久化介质

### 3.1 Parquet（业务数据）

基本约定：

- 日频、分钟频数据使用 Hive 分区：`date=YYYY-MM-DD/part.parquet`
- 一个交易日一个分区文件
- 写入采用“先写 `.tmp` 再 `os.replace`”的原子替换方式
- Windows 下用短退避重试穿过并发读锁（`replace_with_retry`）

### 3.2 JSON / JSONL（用户态数据）

集中在 `data/user_data/` 下，用于配置、密钥、会话、事件和任务状态。

## 6. DuckDB 只做内存视图

[`DataStore._register_views`](backend/app/tickflow/repository.py)
使用 `duckdb.connect(":memory:")`，把 Parquet 目录注册为视图：

- `kline_daily`、`kline_enriched`、`kline_minute`
- `instruments`、`instruments_index`、`instruments_etf`、`instruments_ext`
- `financials_metrics`、`financials_income`、`financials_balance_sheet`、`financials_cash_flow`、`financials_shares`
- `depth5`
- 跨资产 union 视图：`kline_daily_all`、`kline_enriched_all`、`kline_minute_all`、`instruments_all`

这些视图主要服务用户自定义 SQL 和冷查询。标识符转义集中在
[`db_safe.py`](backend/app/db_safe.py)。

## 7. 读取路径

- **热路径**：Polars 内存缓存（最新日 enriched、instruments、完整 enriched 历史、历史股本等）。
- **分钟 / 历史日 K**：`pl.scan_parquet`，带谓词下推。
- **冷查询 / 自定义 SQL**：DuckDB 内存视图。

## 8. 重要设计点：enriched 只落窄表

enriched 磁盘 schema 定义在
[`parquet.py`](backend/app/parquet.py) 的 `ENRICHED_STORAGE_SCHEMA`，
大约只存：

- `symbol`、`date`
- `open`、`high`、`low`、`close`、`volume`、`amount`
- `raw_close`、`raw_high`、`raw_low`
- `turnover_rate`
- `consecutive_limit_ups`、`consecutive_limit_downs`
- `quote_ts`

MA、MACD、KDJ、RSI、各类 `signal_*` 等指标不落盘，
读取时由 `compute_indicators` / `compute_signals` 现算，
并缓存在 `KlineRepository` 的内存里，避免把海量指标列写成永久宽表。

## 9. 一致性与原子性

- 日频写入：`_write_daily_partition`
  - 按 `date` 分区
  - 读旧文件合并
  - `unique(subset=["symbol", "date"], keep="last")` 做 upsert
- enriched 写入：`EnrichedPublication`
  - `.matrix_generation_{asset}.json` 版本标记
  - `.matrix_generation_{asset}.lock` 文件锁
  - `fsync` + 原子替换
  - 保证读端要么看到完整旧版、要么看到完整新版，不会读到半写状态

## 10. 一句话总结

行情和衍生数据是本地 Parquet 分区文件，配置和事件是 `data/user_data` 下的
JSON/JSONL，DuckDB 只是把这些 Parquet 挂成内存视图来支持 SQL 查询，
真正的实时热数据靠进程内 Polars 缓存。
